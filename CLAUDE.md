# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Analysis of token embeddings produced by a weather encoder trained on the ERA5 dataset. Current goal: implement a **k-means-based subspace clustering** algorithm to understand the structure of the tokens. Requirements:

- Must finish in **≤ ~6 hours** wall time on this machine.
- Must output the **subspace bases** (per-cluster basis vectors), not just cluster assignments.
- Token selection: planned approach is a parameter `k` that samples tokens uniformly at random across **all** latent files (not per-file).
- Open design decisions: how many SVD/power iterations to use for the per-cluster subspace estimation, or whether full PCA per cluster is preferable (e.g. `torch.pca_lowrank` / `torch.svd_lowrank` on GPU).

## Data

`latents_2/` — 1.2 TB, **13,021 files** `latent_{i}.pt` for `i = 0 … 13020` (complete, no gaps). Ignore `latents_2/scp_transfer.log`.

Each file is a pickled dict (load with `torch.load(path, map_location="cpu", weights_only=False)`):

| key | content |
|---|---|
| `idx` | scalar int64 tensor (sample index) |
| `latent` | float32 tensor of shape **`[1, 12288, 2048]`** |

Important details:

- The latent has a **leading batch dim of 1** — squeeze it; the real shape is `[12288, 2048]`.
- `12288` = HEALPix cells (nside=32 grid, 12·32²), one token per cell. `2048` = embedding dim per token.
- The cell index uses **NESTED HEALPix ordering** (confirmed 2026-06-12: the dominant-cluster world map is geographically coherent under NESTED, noise under RING — see `runs/clustering/v6_subspace_big_d64/maps/map_annual.png`). Pure-numpy `healpix_nest2ring` / `healpix_ring_lonlat` helpers for cell→lon/lat live in `worldmap.py` (shared by the report + the temporal report).
- **Time axis:** the files are ERA5 states at **6-hourly cadence (4/day: 00/06/12/18 UTC)**. The stored `idx` is the integer sample index, *not* a timestamp — reconstruct the calendar date positionally as `datetime = 2014-01-01 00:00 UTC + idx×6h` (file 0 = 2014-01-01 00:00; file 13020 = 2022-11-30 00:00 — a full 9-yr 2014→2022 ERA5 range would reach 2022-12-31 18:00, ~127 more steps, so the last ~month of 2022 is not fully covered). `temporal_spatial.py` groups files into calendar months this way.
- One file ≈ 100 MB float32. The full dataset (1.2 TB) does **not** fit in RAM (512 GB), so any full-data pass must stream files. Total token count is 13,021 × 12,288 ≈ 160 M tokens.
- Sampling tokens "randomly across all latents" still requires opening every touched file (~100 MB read per file), so I/O dominates — group sampled token indices by file and read each file at most once.

## Hardware / Environment

- 48-core CPU, 512 GB RAM, 2× NVIDIA A100 40 GB.
- Python: `/usr/bin/python3` (no venv), PyTorch 2.6.0 with CUDA, both GPUs visible.
- No build/lint/test tooling exists; these are standalone scripts run directly: `python3 src/<role>/script.py` (long runs via `nohup`).
- **GPU peer-to-peer is silently broken on this machine**: `tensor.to()` directly between `cuda:0` and `cuda:1` returns zeros/garbage without any error (`can_device_access_peer` still reports True). Always route inter-GPU transfers through CPU (`.cpu()` then `.to(other_gpu)`), and do D2H copies from the thread that launched the producing kernels.

## Code

See **README.md** for full documentation. Always keep README.md and this section up to date when changing code (user requirement: every script must be documented).

- **`docs/PIPELINE.md`** — architecture / dataflow doc: how the six stages chain (sample → cluster → holdout → full-dataset replay → reports → forecast-error track), plus the cross-stage invariant table that catches regressions. Written 2026-08-04.
- **`docs/KERNEL.md`** — pedagogical explainer for the assignment kernel's matmul expansion (`(a−b)² = a²−2ab+b²` applied twice, once to `x−μ_j` and once to `z = P−c`), written for a reader who is not comfortable with the linear algebra. Exists because the kernel visually reads as plain k-means while actually computing the full orthogonal subspace residual — the recurring point of confusion (see the `distance-is-to-subspace` memory). Key numbers: naive `[B,K,2048]` = 275 GB/batch vs the actual `[B,K,64]` = 32× less.
- **`docs/PCA.md`** — companion to KERNEL.md covering the **M-step** at the same level: mean = optimal anchor, Pythagoras making "maximise captured" ≡ "minimise residual", covariance-as-a-machine (`vᵀCv` = spread along `v`), eigenvalue = spread along its eigenvector, top-d optimal by Courant–Fischer (a theorem, not a heuristic), streamed moments `S/msum/cnt` (memory independent of cluster size, additive ⇒ 2 GPUs), the `DIM-d:` vs `-d:` slicing trap at d=0, monotone convergence to a *local* min (⇒ the seed sweep), and why a `U=0` point re-seed provably cannot recover at large d. Opens with a §0 primer (average-as-balance-point with worked numbers, the 3-4-5 triangle for "capture most ≡ leave least", eigenvalue via a 6-point 45° line whose eigenvalues are 9.33/0). **§8b is the empirical case for subspaces over k-means** (measured 2026-08-04 on 24,576 tokens, files 5000+9000, v6 model): centre-only vs subspace assignment **agree on only 43%** of tokens, centre-only leaves **20.1% more residual** (2262.5 vs 1883.3), and 12% of subspace winners are not even in the 10 nearest centres of 128 — and the comparison is *generous* to the proxy since it reuses v6's subspace-shaped means. This also quantifies why the `U=0` re-seed is hopeless (a 20% handicap vs every rival).

- `src/common/cluster_io.py` — shared sampling/IO layer all clustering scripts (subspace_kmeans, and any k-means/k-center) import: `load_tokens()` (file sampling + parallel load + writes `sample.json`), `sample_fingerprint()`/`load_file_list()`, and `save_model()`/`save_assignments()` which enforce the cross-algorithm `model.pt`/`assignments.pt` schema (required: `U [K,2048,d]` with `d=0` for plain point clusters, `means`, `eigvals`, `trace`, `counts`, `explained_var_ratio`, `config["method"]`, `history`, `sampled_files`, `sample_fingerprint`; optional: `radius [K]` for k-center's minimax objective, `final_obj_per_token` = the objective/token of the *saved* model under its final relabel sweep — the true minimised residual holdout_eval.py compares the held-out objective against; absent in older runs, fall back to `history[-1]["obj_per_token"]`). Also exports the shared `OVERFIT_GAP_THRESHOLD = 0.03` overfit cutoff used by both `holdout_eval.py` and the report's held-out verdict. K-means is the `d=0` case of K-subspaces (the residual formula collapses to plain squared distance to centroid). `load_tokens`'s `--max-ram-gb` guard counts only the fp16 `data` buffer; true peak RAM also holds the int32 file/cell-id arrays and transient float32 decode buffers (~`load_workers` × 100 MB), so leave headroom.
- `src/clustering/subspace_kmeans.py` — K-subspaces clustering (assignment by orthogonal residual to affine subspaces; per-cluster bases from exact PCA via batched `eigh` of streaming-accumulated 2048×2048 covariances; both GPUs used via one thread per GPU, accumulators merged on CPU). Defaults: 1500 random files × all 12288 tokens (~75 GB RAM), K=64 clusters, d=16, ~7 min wall time. Saves via `cluster_io.save_model`/`save_assignments`. A final relabel sweep under the saved bases writes `assignments.pt` and reconciles `counts` to those final labels (so `model['counts'] == bincount(assignments label)`); that sweep's objective is stored as `final_obj_per_token` (the `history` entries are the *previous* model's objective, one step behind the saved model). Use `--files-from <dir>/sample.json` to cluster a new config on the **identical token sample** for direct comparison (runs sharing a fingerprint are comparable; same seed+tokens-per-file reproduces exactly). `--dim 0` runs plain k-means. Tiny clusters (`< max(2d,64)`) are re-seeded by **splitting the largest healthy cluster along its top PC** (both halves inherit its subspace, offset ±1 std along PC1); a plain random-token re-seed can't recover at large `d` because a fresh `U=0` point-seed can't out-compete the rivals' `d`-dim subspaces — this stranded 1 cluster at `d=64` / 2 at `d=128` in earlier runs (v4/v5). `--max-ram-gb` guards the fp16 RAM budget (default 350; a 7000-file sample is ~352 GB, so pass e.g. `--max-ram-gb 420`). **`--soft` = EM on the matching MPPCA mixture** (`C_j = U_j diag(λ_j) U_jᵀ + σ²_j(I−U_jU_jᵀ)`, so `mahal = R_j/σ²_j + Σᵢzᵢ²/λᵢ` and `logdet = Σᵢlog λᵢ + (D−d)log σ²_j` reuse terms the kernel already computes — only two extra `[B,K,d]` einsums). Rationale: ~31% of tokens sit within a 10% residual margin of a second cluster, so hard labels discard real information *and* inject seed noise; the partition barely moves (~3.7% flips), the point is per-token uncertainty. Responsibilities are **truncated to `--soft-topm`** (default 4) so the M-step costs ~m× not K×; iteration 1 is always hard (no bases yet). Adds `sigma2`/`mixing`/`soft_counts` to `model.pt` and `resp_idx [T,m]` int16 + `resp_w [T,m]` float16 to `assignments.pt` — all additive, `label` stays the argmax and `counts` stays the integer bincount, so every existing reader is unaffected. **`--soft-temp` matters:** at T=1 (literal likelihood) the D=2048 score is so peaked that responsibilities come out one-hot (measured mean top-1 = 0.993) and the run is just slow hard k-subspaces; the likelihood counts 2048 independent dims when the data has ~121 effective ones, so **T ≈ 2048/121 ≈ 17** de-overcounts it. **The empirical validation of T=17 was RETRACTED 2026-08-04** — an earlier smoke test (mean top-1 0.877, 37.2% below 0.9, claimed to "match" the ~31% near-tie fraction) does not hold at scale: the production v10 run (7000 files × 25 iters) measures **mean top-1 0.950, 15.1% below 0.9, 0.9% below 0.5**. The smoke test was 300 files × 3 iters with dozens of re-seeded clusters, so its tokens genuinely were ambiguous under a bad fit; and the two quantities never measured the same thing anyway — the residual margin uses only `R`, while the MPPCA likelihood also uses `zᵢ²/λᵢ`, `σ²_j`, the log-det volume term and the mixing weights, i.e. strictly more information, so it is legitimately more decisive. T=17 still follows from the effective-dimension argument (a property of the data, not of that run), but it is now an **unvalidated prior, not a calibrated choice**. Matching the measured ~33% margin ambiguity would need T≈30–40 — cheap to test by **rescoring the saved v10 model at several T without refitting**. Never re-cite the 0.877/37.2% pair as validation. `σ²` is floored (`SIGMA2_FLOOR = 1e-3`) against the classic EM collapse.
- `src/clustering/holdout_eval.py` — generalization check. Freezes a run's trained means/bases and replays the exact assignment residual (`‖x−μ_j‖²−‖Uⱼᵀ(x−μ_j)‖²`) on tokens from latent files **disjoint from `sampled_files`**, reporting held-out vs in-sample residual fraction (writes `<dir>/holdout.json`; `analyze_clusters.py` then renders a "Held-out generalization" section). Reuses `cluster_io.load_tokens` by handing it an explicit held-out file list (its manifest goes to a throwaway `<dir>/holdout/` subdir, not the run's `sample.json`). Single GPU. Verified v6 (K=128, d=64): held-out 31.5% vs in-sample 31.5% residual — subspaces generalize, not overfitting.
- `src/analysis/file_signature.py` — per-FILE regime signature + subspace residual over **all 13,021 files** (the timestamp-selection coordinate system for goal 1 of the WGen-training analysis). Replays `holdout_eval.py`'s exact frozen-assignment kernel (`‖x−μ_j‖²−‖Uⱼᵀ(x−μ_j)‖²`) but reduces **per file** instead of per held-out set: `mix [K]` (regime-mix fingerprint), `mean_residual` + `residual_frac` (= `mean_residual/mean_total`; ~31.5% globally, outliers = the anomalous/hard-to-encode timestamps), `rare_exposure` (share of the file's tokens in the bottom-quartile-rarest clusters), and the reconstructed date (`2014-01-01 + idx×6h`; `idx`==file id, confirmed). **Streams in batches** (`--batch-files`, default 500 ≈ 25 GB fp16 each) because the full ~656 GB fp16 dataset exceeds 512 GB RAM; assigns on a **single GPU** (I/O-bound at ~17 files/s ⇒ ~13 min, so the broken GPU P2P never enters) and `index_add_`-scatters per-token results into `[N_FILES]`-wide accumulators. Built-in correctness check: the count-weighted mean of `mean_residual` reproduces `model['final_obj_per_token']` (v6: 1887.16 over the held-out files, matching `holdout.json` to 4 sig figs). Outputs `<out>/{signatures.npz, file_summary.csv, cluster_mix.csv, manifest.json, report.md, residual_map.npy, label_map.npy}`; `cluster_mix.csv` is the feature matrix for k-center / diversity timestamp selection. `--files-from`/`--limit` for subsets (smoke-test `--limit 200`). Full v6 run lives in `runs/signatures/v6_d64/`. **Per-cell outlier maps** (the main deliverable for the outlier/fine-tuning goal): the kernel already computes a residual per HEALPix cell, so instead of only reducing it away the script also writes `residual_map.npy [N,12288] float32` (0.60 GiB) and `label_map.npy [N,12288] int16` — outlier detection at per-cell-per-timestep instead of per-timestep resolution. Rows follow the **sorted file list** (row *i* ↔ `file_ids[i]`, same order as `signatures.npz`), not file id, so subsets stay dense; both are `.npy` memmaps (`mmap_mode="r"`). Verified invariants: a row's mean reproduces its `mean_residual` (6e-08 rel) and a row's label histogram reproduces its `mix` (6e-10). **Always normalise before ranking outliers** — per-cell mean residual spans 15.7× (273…4276), so use the climatology `cell_mean_residual`/`cell_std_residual` now in `signatures.npz`: `z = (R − cell_mean)/cell_std`. Same NESTED `[T,12288]` grid as `err_persist.npy` ⇒ gathers directly; intersect to separate "anomalous because rapidly changing" from "anomalous because unmodelled". `--no-cell-maps` skips them. **Assignment margin (2026-08-04):** the kernel ranks each token against all K subspaces, so `topk(2)` instead of `min(1)` gives the runner-up free ⇒ `margin(x) = (R₂−R₁)/R₁`, near-tie = `margin < NEAR_TIE = 0.10`. This is the **subspace-native analogue of the silhouette coefficient**, which does *not* transfer (silhouette assumes Euclidean distance to a centroid + spherical clusters). Reduced per **cluster** (`cluster_margin.csv`: `margin_mean`, `near_frac`, `runner_up`/`runner_up_frac` from the `[K,K]` runner-up confusion matrix), per **file** (`mean_margin`/`near_frac` in `file_summary.csv` — a hardness axis independent of `residual_frac`), and per **cell** (`margin_map.npy [N,12288]` float16, clipped at `MARGIN_CLIP=10`). Decomposes the previously-known global ~31% near-tie figure by cluster. Verified invariants: `margin_map` row-mean reproduces `mean_margin` (4e-06 rel), `cluster_tokens` == `bincount(label_map)` exactly, confusion row-sums == `cluster_tokens`, zero diagonal (runner-up ≠ self).
