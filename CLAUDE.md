# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Analysis of token embeddings produced by a weather encoder trained on the ERA5 dataset. Current goal: implement a **k-means-based subspace clustering** algorithm to understand the structure of the tokens. Requirements:

- Must finish in **≤ ~6 hours** wall time on this machine.
- Must output the **subspace bases** (per-cluster basis vectors), not just cluster assignments.
- Token selection: planned approach is a parameter `k` that samples tokens uniformly at random across **all** latent files (not per-file).
- Open design decisions: how many SVD/power iterations to use for the per-cluster subspace estimation, or whether full PCA per cluster is preferable (e.g. `torch.pca_lowrank` / `torch.svd_lowrank` on GPU).

## Data

`latents_2/` — 1.2 TB, **13,021 files** `latent_{i}.pt` for `i = 0 … 13020` (complete, no gaps). Ignore `latents_2/scp_transfer.log`.

Each file is a pickled dict (load with `torch.load(path, map_location="cpu", weights_only=False)`):

| key | content |
|---|---|
| `idx` | scalar int64 tensor (sample index) |
| `latent` | float32 tensor of shape **`[1, 12288, 2048]`** |

Important details:

- The latent has a **leading batch dim of 1** — squeeze it; the real shape is `[12288, 2048]`.
- `12288` = HEALPix cells (nside=32 grid, 12·32²), one token per cell. `2048` = embedding dim per token.
- The cell index uses **NESTED HEALPix ordering** (confirmed 2026-06-12: the dominant-cluster world map is geographically coherent under NESTED, noise under RING — see `runs/clustering/v6_subspace_big_d64/maps/map_annual.png`). Pure-numpy `healpix_nest2ring` / `healpix_ring_lonlat` helpers for cell→lon/lat live in `worldmap.py` (shared by the report + the temporal report).
- **Time axis:** the files are ERA5 states at **6-hourly cadence (4/day: 00/06/12/18 UTC)**. The stored `idx` is the integer sample index, *not* a timestamp — reconstruct the calendar date positionally as `datetime = 2014-01-01 00:00 UTC + idx×6h` (file 0 = 2014-01-01 00:00; file 13020 = 2022-11-30 00:00 — a full 9-yr 2014→2022 ERA5 range would reach 2022-12-31 18:00, ~127 more steps, so the last ~month of 2022 is not fully covered). `temporal_spatial.py` groups files into calendar months this way.
- One file ≈ 100 MB float32. The full dataset (1.2 TB) does **not** fit in RAM (512 GB), so any full-data pass must stream files. Total token count is 13,021 × 12,288 ≈ 160 M tokens.
- Sampling tokens "randomly across all latents" still requires opening every touched file (~100 MB read per file), so I/O dominates — group sampled token indices by file and read each file at most once.

## Hardware / Environment

- 48-core CPU, 512 GB RAM, 2× NVIDIA A100 40 GB.
- Python: `/usr/bin/python3` (no venv), PyTorch 2.6.0 with CUDA, both GPUs visible.
- No build/lint/test tooling exists; these are standalone scripts run directly: `python3 src/script.py` (long runs via `nohup`).
- **GPU peer-to-peer is silently broken on this machine**: `tensor.to()` directly between `cuda:0` and `cuda:1` returns zeros/garbage without any error (`can_device_access_peer` still reports True). Always route inter-GPU transfers through CPU (`.cpu()` then `.to(other_gpu)`), and do D2H copies from the thread that launched the producing kernels.

## Code

See **README.md** for full documentation. Always keep README.md and this section up to date when changing code (user requirement: every script must be documented).

- `cluster_io.py` — shared sampling/IO layer all clustering scripts (subspace_kmeans, and any k-means/k-center) import: `load_tokens()` (file sampling + parallel load + writes `sample.json`), `sample_fingerprint()`/`load_file_list()`, and `save_model()`/`save_assignments()` which enforce the cross-algorithm `model.pt`/`assignments.pt` schema (required: `U [K,2048,d]` with `d=0` for plain point clusters, `means`, `eigvals`, `trace`, `counts`, `explained_var_ratio`, `config["method"]`, `history`, `sampled_files`, `sample_fingerprint`; optional: `radius [K]` for k-center's minimax objective, `final_obj_per_token` = the objective/token of the *saved* model under its final relabel sweep — the true minimised residual holdout_eval.py compares the held-out objective against; absent in older runs, fall back to `history[-1]["obj_per_token"]`). Also exports the shared `OVERFIT_GAP_THRESHOLD = 0.03` overfit cutoff used by both `holdout_eval.py` and the report's held-out verdict. K-means is the `d=0` case of K-subspaces (the residual formula collapses to plain squared distance to centroid). `load_tokens`'s `--max-ram-gb` guard counts only the fp16 `data` buffer; true peak RAM also holds the int32 file/cell-id arrays and transient float32 decode buffers (~`load_workers` × 100 MB), so leave headroom.
- `subspace_kmeans.py` — K-subspaces clustering (assignment by orthogonal residual to affine subspaces; per-cluster bases from exact PCA via batched `eigh` of streaming-accumulated 2048×2048 covariances; both GPUs used via one thread per GPU, accumulators merged on CPU). Defaults: 1500 random files × all 12288 tokens (~75 GB RAM), K=64 clusters, d=16, ~7 min wall time. Saves via `cluster_io.save_model`/`save_assignments`. A final relabel sweep under the saved bases writes `assignments.pt` and reconciles `counts` to those final labels (so `model['counts'] == bincount(assignments label)`); that sweep's objective is stored as `final_obj_per_token` (the `history` entries are the *previous* model's objective, one step behind the saved model). Use `--files-from <dir>/sample.json` to cluster a new config on the **identical token sample** for direct comparison (runs sharing a fingerprint are comparable; same seed+tokens-per-file reproduces exactly). `--dim 0` runs plain k-means. Tiny clusters (`< max(2d,64)`) are re-seeded by **splitting the largest healthy cluster along its top PC** (both halves inherit its subspace, offset ±1 std along PC1); a plain random-token re-seed can't recover at large `d` because a fresh `U=0` point-seed can't out-compete the rivals' `d`-dim subspaces — this stranded 1 cluster at `d=64` / 2 at `d=128` in earlier runs (v4/v5). `--max-ram-gb` guards the fp16 RAM budget (default 350; a 7000-file sample is ~352 GB, so pass e.g. `--max-ram-gb 420`).
- `holdout_eval.py` — generalization check. Freezes a run's trained means/bases and replays the exact assignment residual (`‖x−μ_j‖²−‖Uⱼᵀ(x−μ_j)‖²`) on tokens from latent files **disjoint from `sampled_files`**, reporting held-out vs in-sample residual fraction (writes `<dir>/holdout.json`; `analyze_clusters.py` then renders a "Held-out generalization" section). Reuses `cluster_io.load_tokens` by handing it an explicit held-out file list (its manifest goes to a throwaway `<dir>/holdout/` subdir, not the run's `sample.json`). Single GPU. Verified v6 (K=128, d=64): held-out 31.5% vs in-sample 31.5% residual — subspaces generalize, not overfitting.
- `file_signature.py` — per-FILE regime signature + subspace residual over **all 13,021 files** (the timestamp-selection coordinate system for goal 1 of the WGen-training analysis). Replays `holdout_eval.py`'s exact frozen-assignment kernel (`‖x−μ_j‖²−‖Uⱼᵀ(x−μ_j)‖²`) but reduces **per file** instead of per held-out set: `mix [K]` (regime-mix fingerprint), `mean_residual` + `residual_frac` (= `mean_residual/mean_total`; ~31.5% globally, outliers = the anomalous/hard-to-encode timestamps), `rare_exposure` (share of the file's tokens in the bottom-quartile-rarest clusters), and the reconstructed date (`2014-01-01 + idx×6h`; `idx`==file id, confirmed). **Streams in batches** (`--batch-files`, default 500 ≈ 25 GB fp16 each) because the full ~656 GB fp16 dataset exceeds 512 GB RAM; assigns on a **single GPU** (I/O-bound at ~17 files/s ⇒ ~13 min, so the broken GPU P2P never enters) and `index_add_`-scatters per-token results into `[N_FILES]`-wide accumulators. Built-in correctness check: the count-weighted mean of `mean_residual` reproduces `model['final_obj_per_token']` (v6: 1887.16 over the held-out files, matching `holdout.json` to 4 sig figs). Outputs `<out>/{signatures.npz, file_summary.csv, cluster_mix.csv, manifest.json, report.md}`; `cluster_mix.csv` is the feature matrix for k-center / diversity timestamp selection. `--files-from`/`--limit` for subsets (smoke-test `--limit 200`). Full v6 run lives in `runs/signatures/v6_d64/`.
- `worldmap.py` — shared HEALPix geometry + cluster coloring + world-map renderer, imported by both `analyze_clusters.py` and `temporal_spatial.py`. Pure-numpy `healpix_nest2ring` / `healpix_ring_lonlat` (cell→lon/lat), validated data-free: `nest2ring` is a bijection of `[0,12288)`; lon/lat clean (lat ∈ [−88.5°, 88.5°]); equal-area cell distribution matches analytics (50.0% at |lat|<30°; 13.7% at |lat|>60° vs 13.4% theoretical). `build_affinity_matrix` (subspace-affinity [K,K] for d>0, else centroid cosine) and `affinity_ordered_colors` (Fiedler-vector spectral seriation → `turbo`, so similar clusters share hues). `get_coastlines()` fetches+caches the Natural Earth 110m coastline GeoJSON (stdlib `json`, no cartopy/shapely needed). `render_world_map()` draws a Mollweide map with two readability features: **continent outlines** and a smooth **heatmap** (per-cell RGB interpolated via `scipy.griddata` onto a regular grid + Gaussian-smoothed, painted with `pcolormesh` — replaces the old speckled 12,288-pixel scatter; ~0.8 s/map). RGB (not the categorical cluster id) is interpolated, valid because `affinity_ordered_colors` already makes similar clusters share colors. `render_change_map()` maps *where* the dominant cluster differs between two periods (unchanged cells muted, flipped cells colored by transition) and returns the top source→destination pair legend for the report.
- `analyze_clusters.py` — algorithm-agnostic Markdown report generator; reads any `model.pt`/`assignments.pt` following the `cluster_io.py` schema (convergence, variance decomposition, per-cluster spatial/temporal columns, subspace affinity when `d>0`, optional held-out section from `holdout.json`, token-sample fingerprint + reproduce command). The **world map and the temporal/seasonal analysis have moved** to the dedicated `temporal_spatial.py` report; this report keeps the compact per-cluster spatial/temporal columns and a pointer to `temporal_report.md`. Every table is now preceded by an "Overview"/"How to read this" block naming the `model.pt` fields it derives from, so `report.md` stands alone. Imports `build_affinity_matrix` (for the affinity table) from `worldmap.py`. Backfills `sample.json` for pre-manifest runs. `python3 src/analyze_clusters.py --dir <out_dir> --out <report.md>`. **Every report metric is defined/interpreted in `docs/METRICS.md`** — keep it in sync.
- `temporal_spatial.py` — dedicated **temporal & spatial report** (`temporal_report.md`): 12 monthly dominant-cluster maps + an annual map (continent outlines + heatmap via `worldmap.py`), 4 **seasonal** maps (`SEASONS`, NH convention — DJF wraps the year boundary, December grouped with the *following* Jan/Feb) + season-to-season stability, a monthly-enrichment table flagging seasonal clusters, a month-to-month dominant-cluster flip-rate curve (incl. the Dec→Jan wrap), and **Jan→Jul change maps** (`map_change_jan_jul.png` / `map_change_jul_dest.png` via `worldmap.render_change_map`) with the top transitions tabulated. Builds the file→calendar-month mapping from `START + idx×6h` and reuses the run's *existing* `assignments.pt` (v6 covers all 12,288 cells in every calendar month, ~528–623 files/month) so it needs **no recomputation** — a ~10 s rendering/reporting pass. Colors computed once (`affinity_ordered_colors`) and shared across all maps. `python3 src/temporal_spatial.py --dir <run>`.
- **`docs/wgen_architecture.md`** — architecture map of the upstream ECMWF **WeatherGenerator** model (cloned read-only to `/home/psaher/WeatherGenerator`, `git clone --depth 1` of github.com/ecmwf/WeatherGenerator), produced by a 6-reader dynamic workflow to ground the forecast-error work. All HIGH-confidence findings: the `ForecastingEngine` is **latent→latent 2048-d** (`engines.py:564-636`, `model.py:703`, comment "roll-out in latent space") — so `forecast_engine(latents_2[t])` predicts `latents_2[t+1]` and **both sides already exist on disk; no encoder/decoder/ERA5 needed**; `latents_2`'s `latent [1,12288,2048]` **is** the encoder output `tokens_global` (`encoder.py:140`); NESTED ordering is set in the tokenizer layer (`datasets/utils.py`); the model is **fully dense, zero MoE** (FFN slot = `layers.py` MLP; top MoE target = the 16 `ForecastingEngine` blocks); **two training recipes** — base `config_forecasting.yml` trains encoder+forecast jointly (`freeze_modules: ""`), but finetuning `config_forecasting_finetuning.yml` freezes the whole assimilation stack (`freeze_modules` regex `global|local|adapter|q_cells|latent|ERA5` via `re.fullmatch` over `named_modules`) so **only `forecast_engine` + decoder `pred_heads` refine** (encoder frozen), and `latents_2`'s 2014–2022 window matches that finetuning config ⇒ likely a frozen-encoder embedding; timestep sampling is **uniform random, no weighting** (hook = `multi_stream_data_sampler.py` `reset()`/`_calc_baseperms` — must be inlined since it's an `IterableDataset`, so `WeightedRandomSampler` can't drop in); **no code computes per-cell latent forecast error** today (eval averages out cells in physical space). §4 is the concrete supercomputer plan: extract `err.npy [13020,12288]` (single-step latent residual ‖pred−truth‖²) which gathers **directly** onto `assignments.pt` (both NESTED — no remap). Open Q to verify on the supercomputer: confirm `latents_2[t]` is the step-0 encoder state feeding `forecast_engine` (decode check), and pin the production checkpoint's config + `rope_coords`.
- `persistence_error.py` — model-free, local **persistence baseline** the WGen repo lacks. `err_persist[t,cell] = ‖x_t[cell] − x_{t+1}[cell]‖²` → `[13020,12288]` float32 (skill-score denominator + a 6h-tendency/changeability measure). Threaded-prefetch streamer, CPU-only (~15 min for the 1.3 TB; no checkpoint/GPU). Integrity-verified independently (recompute from raw latents → 0.00e+00 rel-error). Full run in `runs/persistence/v6/` (global mean ≈3149.6); outputs `{err_persist.npy, meta.json}` with `source_idx`/`target_idx`/`source_dt`/`n_transitions` (local key `idx`, `--key` overrides for the supercomputer's `idx_num`).
- `extract_forecast_error.py` — **supercomputer-only** (no checkpoint on this box). `err_forecast[t,cell] = ‖forecast_engine(x_t, step=0, rope_coords) − x_{t+1}‖²` alongside the persistence baseline, same `[13020,12288]` contract. Loads the checkpoint via `init_model_and_shard` and **aborts if `skill = 1 − mean_fc/mean_ps ≤ 0`** on the first batch — that self-check settles wgen_architecture §6.1's blocking question (wrong input/rope/config ⇒ skill≤0). - `analyze_forecast_error.py` — local analyzer: per-cell error → goal-1 (training-timestamp weights) + goal-2 (embedding understanding). Two modes: **bridge** (only `err_persist.npy`, auto-detected; persistence = 6h-tendency + hardness proxy) and **full** (both npy → latent **skill = 1 − Σfc/Σps**, ratio-of-sums, never mean-of-per-cell-skill). **Attribution** via the static dominant-per-cell map (`mode(label)` per cell over the 7000-file sample); a **free** static-vs-dynamic gate replays the per-token labels in `assignments.pt` on the 7000∩err intersection (validated v6: NMI 0.76–0.78 every month ⇒ static trustworthy; per-cell purity 0.656, zero-cell clusters [13,98] flagged for optional `--dynamic`). **Goal-1 weights** (`weights.csv`) = rank-normalized percentile axes (hardness `h_t`, rare-regime `sig["rare_exposure"]`, diversity=1/`knn_density` in mix-space) fused as weighted **mean** (not product — saturates) through `1+(wmax−1)·s^α`, renorm mean=1. Bridge run in `runs/forecast_error/persist_v6/` (`summary.json`, `per_cluster.csv`, `temporal.csv`, `weights.csv`, `static_vs_dynamic.json`, `report.md`, `maps/`). NOTE `src` doubles as row-axis `0..N-1` AND file-id; `cell*K+lab` bincount reshapes the per-token `assignments.pt` correctly. `map_persist.png` is physically coherent (tropics/storm-tracks high, poles/subtropics low) ⇒ latents encode real atmospheric structure.
